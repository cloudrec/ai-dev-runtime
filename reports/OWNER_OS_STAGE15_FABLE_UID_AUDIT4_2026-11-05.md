Fix: pin inside target() after validation (idempotent, one lstat), or at least in tools/agent_uid_preflight.main after target() succeeds (owner runs it before every trial).
G2 (PLAUSIBLE, low) _pin_path() keys on AGENT_CONTROL_DB; a process with neither variable (hand-run tool, cron) resolves the default /root/ai-dev-runtime/agent_control.db.run_as — another instance's pin — and runs root tooling in this instance's agent tree. G3 (PLAUSIBLE, low) The pin can be removed by anyone who can write dirname(AGENT_CONTROL_DB); preflight checks the DB file, not its directory. Add dirname(AGENT_CONTROL_DB) to the deny probe (`test ! -w`).
G4 (PLAUSIBLE, low, functional not privilege) session_recovery:519/522 hands tmux ONE string -> tmux runs it through the default shell as root; if that shell forks instead of exec'ing the last command, the pane pid is a root sh around a dropped claude and every send is refused (pane_uid_mismatch) — the recovered agent is unreachable. dash/bash exec a trailing simple command, so it works in practice; prefixing `exec ` in recovery_command makes it certain.
G5 (CONFIRMED, low) agent_resume order: can_use_dir runs a probe as the agent *before* the pin is written (fine) but api_mode check/`settings_api_overrides` read the agent's ~/.claude as root (open_regular) — acceptable.
