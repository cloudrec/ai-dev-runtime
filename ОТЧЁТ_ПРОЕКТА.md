## 1. НАЗНАЧЕНИЕ ПРОЕКТА

AI Runtime Agent — это постоянно работающий сервис (daemon) на сервере, который:

- принимает команды на естественном языке (русский),
- парсит команду и определяет намерение (intent),
- планирует шаги для выполнения,
- применяет изменения к файлам проекта,
- выполняет Git-операции (с автоматическим коммитом),
- перед каждым изменением создаёт резервную копию,
- после изменений проверяет проект (синтаксис, импорты, тесты),
- в случае ошибки — откатывается к резервной копии,
- всё это работает асинхронно через очередь задач и REST API.

Сервис — основа AI Dev Runtime для автоматизации разработки и администрирования проектов.

## 4. ПОДРОБНО ПО КАЖДОМУ МОДУЛЮ

### 4.1. `runtime/engine.py` — Оркестратор
Главный класс `RuntimeEngine`. Цепочка выполнения:
1. **build_context()** — собирает контекст (git status, список файлов проекта)
2. **parse_command()** — разбирает команду, определяет intent
3. **plan_task()** — составляет план шагов
4. **execute_plan()** — исполняет план

### 4.2. `core/parser.py` — Парсер команд
Определяет намерение (intent) по ключевым словам:
- «лог» → `add_logging`
- «api» → `create_api`
- остальное → `general`

### 4.3. `core/planner.py` — Планировщик
По intent составляет шаги:
- `add_logging` → ["create logger", "inject logger"]
- `create_api` → ["setup fastapi", "add routes"]
- `general` → ["analyze manually"]

### 4.4. `core/executor.py` — Исполнитель (v0.6)
Исполняет план. Цепочка:
1. **BackupEngine.snapshot()** — резервная копия перед изменениями
2. **выполнение шагов** — каждый шаг проходит проверку safety
3. **Validator.check_all()** — проверка после изменений
4. **Git commit** — только если валидация прошла
5. **Rollback** — если валидация упала, откат к бэкапу

### 4.5. `core/file_engine.py` — File Engine
Полный набор файловых операций (все с safety-проверкой):

| Операция | Описание |
|---|---|
| `create_file()` | Создать файл (ошибка, если существует) |
| `replace_file()` | Полностью заменить содержимое |
| `replace_block()` | Заменить блок кода между маркерами |
| `insert_at()` | Вставить код после строки с маркером |
| `delete_file()` | Удалить файл |
| `create_dir()` | Создать директорию |

Все операции проверяются через `safety.validate_file_operation()` — выход за пределы проекта блокируется.

### 4.6. `core/safety.py` — Безопасность действий
- `approve_action()` — разрешает/запрещает шаги (whitelist + блок опасных слов)
- `is_path_safe()` — проверяет, что путь внутри разрешённой директории
- `validate_file_operation()` — защита от `..` и выхода за пределы проекта
- Опасные ключевые слова: `rm`, `sudo`, `shutdown`, `drop`, `delete`, `format`, `mkfs`

### 4.7. `core/task_queue.py` — Очередь задач
Потокобезопасная очередь (FIFO) с фоновым worker-потоком.

Каждая задача содержит:
- `id` — UUID
- `command` — команда
- `project_path` — путь к проекту
- `status` — `pending | running | done | failed`
- `created_at / started_at / finished_at` — временные метки
- `log` — пошаговый лог выполнения
- `result` — результат
- `error` — ошибка (если есть)

Методы: `submit()`, `get()`, `status()`, `list()`, `stop()`.

### 4.8. `core/backup_engine.py` — Backup Engine
- `snapshot(reason)` — создаёт tar.gz-бэкап (без .git, venv, pycache)
- `list_backups()` — история (новые сверху)
- `rollback(backup_id)` — восстановление из бэкапа (+ страховочный snapshot перед откатом)
- `get_latest()` — последний бэкап
- авт cleaning по лимиту `max_backups`

Бэкапы хранятся в `.ai-runtime-backups/`.

### 4.9. `core/validator.py` — Проверка после изменений
Запускается перед commit. Три проверки:

| Проверка | Что делает |
|---|---|
| **syntax** | `py_compile` всех .py файлов проекта |
| **imports** | пробует `import core`, `import runtime`, `import api` |
| **tests** | запускает pytest, если есть `tests/test_*.py` |

Если хоть одна проверка упала — `passed: false`, executor откатывает изменения.

### 4.10. `core/security.py` — Security (API Key + HMAC)
- `check_api_key()` — проверка заголовка `X-API-Key` (constant-time)
- `check_hmac()` — HMAC-SHA256 подпись (`X-Signature` + `X-Timestamp`) с защитой от replay (окно 5 мин)
- `is_public_path()` — пути без авторизации (`/health`, `/docs`, `/openapi.json`)
- Если ключи не настроены в `.env` — dev-режим (авторизация отключена)

### 4.11. `core/git_bridge.py` — Git Engine
- `status()` — git status
- `add_all()` — git add .
- `commit(message)` — git commit -m
- `push()` — git push (отключён по умолчанию для безопасности)

### 4.12. `core/patch_engine.py` — Patch Engine
- `apply_patch()` — создаёт unified diff, записывает новое содержимое

### 4.13. `api/main.py` — REST API
FastAPI сервер. Эндпоинты:

| Метод | Путь | Описание |
|---|---|---|
| POST | `/run` | Синхронный запуск команды (legacy) |
| POST | `/task` | Создать асинхронную задачу → возвращает `task_id` |
| GET | `/status/{task_id}` | Статус задачи |
| GET | `/tasks` | Список всех задач |
| GET | `/health` | Здоровье сервиса (uptime, tasks count) |
| GET | `/logs` | Логи всех задач |
| GET | `/logs/{task_id}` | Логи конкретной задачи |
| POST | `/shutdown` | Остановка воркера очереди |
| GET | `/docs` | Swagger UI (автодокументация) |
| GET | `/openapi.json` | OpenAPI-схема |

Дополнительно: `AuthMiddleware` — проверка API Key и HMAC на всех эндпоинтах, кроме публичных.

### 4.14. `cli/runtime.py` — CLI
```bash
python cli/runtime.py "добавь логирование" /root/ai-dev-runtime
```
Добавляет корень проекта в `sys.path`, запускает `RuntimeEngine.run()`.

## 10. ЦЕПОЧКА ВЫПОЛНЕНИЯ ЗАДАЧИ (END-TO-END)

```
Команда "добавь логирование"
  │
  ├─► CLI / API принимает команду
  │
  ├─► TaskQueue.submit() → UUID, статус pending
  │
  ├─► Worker поток берёт задачу → статус running
  │
  ├─► RuntimeEngine.run():
  │     ├─ build_context()     — git status, список файлов
  │     ├─ parse_command()     — intent = add_logging
  │     ├─ plan_task()         — steps = [create logger, inject logger]
  │     └─ execute_plan():
  │           ├─ BackupEngine.snapshot()   ← резервная копия
  │           ├─ FileWriter.write_file()   ← создание core/logger.py
  │           ├─ Validator.check_all()     ← syntax + imports + tests
  │           ├─ GitBridge.commit()        ← коммит (если ОК)
  │           └─ rollback()                ← откат (если ошибка)
  │
  ├─► Статус → done (или failed)
  │
  └─► Результат доступен через GET /status/{task_id}
```
