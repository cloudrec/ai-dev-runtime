Проект

AI Runtime Agent v0.1

Цель

Создать постоянно работающий сервис на сервере, который принимает безопасные команды, изменяет файлы проекта, выполняет Git-операции и возвращает результат. Сервис проектируется как основа AI Dev Runtime и должен использоваться всеми текущими и будущими проектами.

Основные требования
1. Постоянно работающий daemon

Запускается как systemd service.

После перезагрузки сервера автоматически стартует.

2. REST API

Пример:

POST /task
GET  /status
GET  /health
GET  /logs
POST /shutdown
3. Очередь задач

Все задачи записываются в очередь.

Каждая задача имеет:

UUID
время создания
статус
лог выполнения
результат
ошибки
4. File Engine

Поддерживает:

создать файл
заменить файл полностью
заменить функцию
вставить код
удалить файл
создать директорию

Все операции выполняются только внутри разрешённых директорий.

5. Git Engine

Поддерживает:

status
diff
add
commit
branch
checkout
push
pull

Коммит автоматически получает сообщение.

6. Backup Engine

Перед каждым изменением:

создаётся backup;
хранится история;
поддерживается rollback.
7. Patch Engine

Работает не с "перезаписать файл", а с патчами.

Поддерживает:

unified diff;
поиск функции;
замену блока;
проверку результата.
8. Проверка

После изменения автоматически:

запускается formatter;
запускаются тесты;
проверяется импорт;
только после успешной проверки выполняется commit.
9. Security

Обязательно:

API Key
HMAC подпись
whitelist директорий
запрет на работу вне проекта
журнал всех действий
10. Plugins

Архитектура должна поддерживать плагины:

plugins/

Например:

GitHub
Docker
Python
WordPress
Telegram
PostgreSQL
11. Конфигурация

Через .env

Настраиваются:

пути;
Git;
API;
модели AI;
лимиты.
12. Логи

Структурированные JSON-логи.

13. Docker

Проект должен запускаться одной командой.

14. Документация

Автоматически генерируемый Swagger/OpenAPI.

Но я хочу добавить ещё одну вещь, которая, как мне кажется, будет самой сильной.

Runtime не должен ждать команду.

Он должен иметь режим:

Observe
      ↓
Think
      ↓
Propose
      ↓
(при разрешении)
Apply
      ↓
Verify
      ↓
Commit

То есть он сам:

следит за репозиториями;
анализирует изменения;
ищет новые технологии;
предлагает улучшения;
готовит патчи;
